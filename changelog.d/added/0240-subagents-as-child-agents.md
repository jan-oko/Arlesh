- **Subagents as child agents.** A subagent dispatched from an attached Claude Code session (with the `arlesh-notify` mod) is registered as a child of the session's agent and listed under it in Settings → Agents, where each agent's subagents are folded away until you open them. It claims the Task its brief names, only inside the session's Claim, and sees and writes only that sub-Claim, while the session keeps its whole Claim. When the subagent stops its Claim is paused and the child stays listed as Paused; when it is resumed the Claim resumes. The child is removed when its Task is set Done or its parent agent is removed, and Ctrl+Z on the change that removed it brings it back, paused until its subagent resumes. A subagent that is refused is told why: its Claim is paused, or the node is outside its Claim but inside its parent's, where it may claim it. A child shares its parent's account, so it has no Lock of its own. Write `[arlesh:<task id>]` in an Agent call and the subagent starts already holding that Task, with the Task in its label in Claude Code's subagent list. With the `arlesh-notify` mod a session also attaches again by itself when the server restarts, pauses its own Claim when it ends (and resumes it when it comes back) so a new session can take the subtree, and adopts an attach the model made by hand.
