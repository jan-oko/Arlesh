- **Every node's id is a UUID.** Rows used to be numbered by the database; they are now stored under a UUID, which is what lets a client name a row before the server has seen it. Every existing node keeps the id it always showed as `full_id`, so links, short ids you have written down and the ids agents hold still work (a short id that once needed a fourth character to avoid a row number may now read three; the longer one still resolves). Row numbers are gone: the MCP and the HTTP API refuse a JSON number where an id goes, and read an id only as a prefix (3 or more characters) of a UUID. Every create route, the MCP's `arlesh_tasks.create`, `arlesh_infos.create` and `arlesh_waits` take an optional `id` (a UUID a client chose); without one the server makes a UUIDv7. A Habit occurrence's id changes once, because it is the hash of a key that spells the ids of the rows it is drawn from; what you recorded on an occurrence is kept. The HTTP `api_version` is 2: an app and a server on different sides of this change refuse each other's writes until both are updated. Opening an existing database migrates it once on first start.
