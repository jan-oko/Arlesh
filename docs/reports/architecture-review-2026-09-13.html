The through-line

Arlesh's domain is implemented twice — once in Rust, once in TypeScript — because the Tauri seam is cut at table-CRUD granularity instead of use-case granularity.

Three independent sweeps of the backend, the Mindmap cluster, and the IPC/modal layer each arrived here from a different direction. src/api/ holds 68 functions and zero statements that are not return invoke(…). Because that layer offers no depth to put anything in, orchestration accumulated one level above it — in use-mindmap-data.ts and use-node-editor.ts — where it has no transaction, no invariant enforcement, and in the worst case silently discards user data.

Every candidate below is a variation on moving one domain operation back across that seam, or on splitting a module that grew because there was nowhere else for the knowledge to go.

Top recommendation

Start with #1 — retype_node.

It is the only candidate that is simultaneously an architecture fix and a live data-loss bug: retyping a scoped, planned Task to a Goal silently discards its Time Scope and On-exit behavior today. It is small enough to land alone, it forces the transaction question (#2) into the open on one concrete operation rather than as a sweeping refactor, and it is the first place the legal-parent rule gets a single home instead of four.

It also sets the pattern every later candidate follows: move one domain operation back across the seam, and let the TypeScript that was standing in for it delete rather than move.

Then #2 unit of work → #3 materialization → #6 split FlowRepository. The frontend candidates (#7, #8) get easier after #5, because a load_mindmap command removes most of what use-mindmap-data.ts is doing.
